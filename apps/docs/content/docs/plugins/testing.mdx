---
title: Testing plugins
description: Test the projects create-next-suite generates.
---

`create-next-suite/testing` generates a project and runs its scripts, the way the CI of
create-next-suite checks its own plugins with every package manager:

```ts title="project.test.ts"
import { createTestProject } from 'create-next-suite/testing'
import { expect, test } from 'vitest'

test('the project builds with my plugin and Biome', async () => {
  const project = await createTestProject({
    plugins: ['./my-plugin'],
    answers: { 'my-plugin': true, linter: 'biome' },
    install: true,
  })

  expect((await project.run('build')).isSuccess).toBe(true)
})
```

`plugins` takes the addresses of the plugins under test: a local directory, relative to the
current directory, npm, GitHub, GitLab, Git or a URL. A registry short name is unknown to the
test's own configuration. The plugins are trusted for the test without a question, and nothing is recorded in your user configuration: the run keeps its
cache and configuration in the directory it creates the project in. A plugin without a category is
selected by its name in `answers`, as `--<name>` selects it on the command line.

Every question you leave out takes its default; git stays off. Run the checks of the generated
project, such as `typecheck`, `lint` and `test`.

## Check a plugin

```bash
npx -p create-next-suite next-suite plugin validate ./my-plugin
```

`plugin validate` loads a plugin the way create-next-suite does: it reads its files and its
metadata without running it, checks its category, installs the npm packages of its `package.json`
and runs its `plugin.ts` on its own. It prints the plugin's options and points, and hints where
`create-next-suite` belongs in its `package.json` so `plugin.ts` can be type-checked. It does not
run a type check itself; run `tsc` in the plugin for that.
