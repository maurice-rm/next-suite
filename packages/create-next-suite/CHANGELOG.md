- [#43](https://github.com/maurice-rm/next-suite/pull/43) [`0fae525`](https://github.com/maurice-rm/next-suite/commit/0fae5257a59f0939597cad2997bfd30cef52e0f4) Thanks [@maurice-rm](https://github.com/maurice-rm)! - `next-suite update` takes a change of `next-suite.config.ts` into a generated project and keeps your changes to its files. It generates the old output once more from the commit that last changed the lock, with the version of create-next-suite the lock names (through npm, from its cache where possible, otherwise the running version with a warning), and the new output from the config, formats both the way the project's post-steps did, and merges each file three ways: a file you did not change takes the new output, a file you changed is merged with `git merge-file`, `package.json` key by key, new files are added and files no longer generated are removed only when you did not change them. Merge conflicts get Git's markers or, for a JSON key, both values in the report; the update exits with 1 and waits for `next-suite update --continue` to write the lock. `--dry-run` shows the report without writing, and `--force` updates over uncommitted changes after saving them in the stash. The pending update waits in the Git directory, out of reach of a clone; generated files are never written through links, and other versions and formatters run in work directories beside the plugin cache rather than in the shared temporary directory. A plugin whose content changed since the lock recorded it is named in a warning, and the install runs when the dependencies changed.

### Patch Changes

- [#39](https://github.com/maurice-rm/next-suite/pull/39) [`3d20030`](https://github.com/maurice-rm/next-suite/commit/3d20030b88142be86f29aac86dbf9568a605edcf) Thanks [@maurice-rm](https://github.com/maurice-rm)! - Loading external plugins is hardened. A snapshot already in the cache is hashed again before it is used and written anew when its files differ, and a plugin's npm packages are installed anew on every run, so a changed cache never runs under the trust of the real content. A Git clone runs no hook and no filter of the Git configuration, such as Git LFS, follows no submodules and reads no repository around the cache. Git and the GitHub CLI run in a directory of the cache, so on Windows no program of the current directory starts in their place. `next-suite registry add --replace` forgets the trust and content hashes of the registry it replaces, as `registry remove` does. A registry.json whose plugin descriptions hold control or format characters, such as an escape sequence or a bidi override, does not load, and its JSON schema says so.
